## 真实场景测试（域差距分析）

模型训练完后，拿一段**真实世界的 RM 实车视频**直接测试（手机录屏，1592×720，
29.2 fps，3637 帧，125 秒），不重新训练、不调参数，看它能不能直接用。

| 指标 | 结果 | 对比：渲染图验证集 |
|---|---|---|
| 处理速度 | 42.1 FPS（含解码 + 推理 + 画框 + 编码） | — |
| 单帧推理 | 14.7 ms | 4.7 ms |
| 有检测的帧 | 1611 / 3637（**44.3%**） | 几乎 100% |
| 最高置信度 | sentry 0.81 | 0.96+ |
| 平均置信度 | 0.35 ~ 0.44 | 0.85+ |
| 类别正确率 | **很低**，真装甲板大多被判成 sentry | 0.90 mAP50-95 |

### 结论

1. **能检出，但效果明显退化**。真实场景的置信度掉到 0.35~0.44，
   渲染图上是 0.9+，说明模型对真实纹理不够自信。
2. **类别判错严重**。真实的 2/3/4 号装甲板大量被判成 `sentry`，
   说明它学到的是"渲染图里 sentry 长什么样"，而不是"装甲板的结构特征"。
3. **UI 元素被误检**。画面切到视频网站推荐页后，点赞/收藏/分享按钮
   （圆角矩形 + 高对比色块）被当成装甲板检出，见
   `docs/figures/phone_false_positive.jpg`。

### 原因

训练集 100% 是 Blender 渲染的 warehouse 场景，与户外实拍在
**光照、材质纹理、相机畸变、运动模糊**上差异很大——典型的 domain gap。
这不是代码 bug，是数据分布不一致。

### 改进方向（按性价比排序）

1. **加真实数据做域适配**：哪怕只标 100~200 张真实图混进去，效果通常提升明显
2. **训练时加增强**：随机亮度/对比度、模糊、噪声、色偏，让模型见过"不干净"的画面
3. **半监督**：用当前模型给真实视频打伪标签，人工只修正高置信度的部分
4. **类别合并**：如果只关心"框住装甲板"而不关心编号，先合并成一类 `armor`，
   能直接消除类别判错问题

> 这一段建议写进报告：**知道模型在哪里失效、为什么失效，比只报一个高 mAP 更有说服力。**
